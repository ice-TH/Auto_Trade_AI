==================================================
1. เป้าหมายและขอบเขต
==================================================

สร้างเว็บแดชบอร์ดที่ทำงานบนเครื่องส่วนตัว สำหรับ:
- ติดตามหุ้นสหรัฐฯ
- วิเคราะห์แนวโน้มและแนวรับ/แนวต้าน
- สร้างแผนและตรวจเงื่อนไขเข้า/ออก
- คำนวณ Money Management, Stop Loss และ Take Profit
- จัดเก็บภาพกราฟและข้อมูลประกอบอย่างเป็นระเบียบ
- แสดงประวัติแผน สัญญาณ และออเดอร์พร้อมเหตุผล
- เชื่อมต่อ MT5/Exness สำหรับทดสอบบนบัญชี Demo ภายหลัง

Antigravity เป็นเครื่องมือช่วยสร้างและทดสอบโปรแกรม
ส่วนโปรแกรมที่สร้างต้องทำงานต่อเนื่องได้เองหลังติดตั้ง
ไม่พึ่งการเปิด Agent หรือการสนทนาไว้ตลอดเวลา

==================================================
2. สินทรัพย์และแหล่งข้อมูล
==================================================

ติดตามหุ้น:
- AAPL
- MSFT
- NVDA
- AMZN
- GOOGL หรือ GOOG โดยให้ผู้ใช้เลือกอย่างชัดเจน
- META
- TSLA

GOOGL และ GOOG ต้องถือเป็นคนละสัญลักษณ์
ห้ามสลับหรือรวมข้อมูลโดยอัตโนมัติ

ใช้ข้อมูล Webull เป็นฐานหลักสำหรับ:
- OHLCV
- อินดิเคเตอร์
- แนวรับ/แนวต้าน
- Fibonacci
- Demand/Supply
- การสร้างแผนและสัญญาณ

ใช้ MT5/Exness สำหรับ:
- ตรวจรายละเอียดสัญญาและข้อจำกัดการส่งคำสั่ง
- ราคา Bid/Ask เพื่อประเมินการซื้อขายจริง
- คำนวณความเสี่ยง ต้นทุน และ margin
- ส่งคำสั่ง ติดตามสถานะ และบันทึกผลจริง

ก่อนสร้างตัวเชื่อม:
1. ตรวจเอกสารทางการและสิทธิ์เข้าถึง Webull ของบัญชีผู้ใช้
2. ตรวจข้อมูลย้อนหลัง ข้อมูลสด ความล่าช้า และข้อจำกัด API
3. ตรวจการรองรับข้อมูล DAY, WEEK และ M15
4. ตรวจการจับคู่หุ้นแต่ละตัวกับ CFD ในบัญชี MT5
5. ตรวจสิทธิ์ใช้งานข้อมูล รวมถึงการใช้งานผ่านโปรแกรม
6. สรุปค่าใช้จ่ายหรือข้อจำกัดที่ตรวจสอบได้ให้ผู้ใช้ทราบ

ห้าม:
- สมมติ endpoint หรือใช้ API ที่ไม่มีเอกสารรองรับ
- หลบเลี่ยงข้อจำกัดหรือสิทธิ์เข้าถึงข้อมูล
- ถือว่าข้อมูลที่เห็นฟรีในแอปใช้ผ่าน API ได้ฟรีเสมอ
- เปลี่ยนแหล่งข้อมูลวิเคราะห์โดยไม่ขออนุมัติ

หากเข้าถึงข้อมูลจริงไม่ได้:
- สร้าง mock adapter หรือรองรับการนำเข้าไฟล์ที่ผู้ใช้มีสิทธิ์ใช้
- แสดงป้าย “ข้อมูลจำลอง” หรือ “ข้อมูลย้อนหลัง” ชัดเจน
- ปิดการส่งคำสั่งซื้อขาย

==================================================
3. TimeFrame และแนวทางหลัก
==================================================

ใช้:
- WEEK: บริบทแนวโน้มใหญ่และโซนสำคัญ
- DAY: กรอบหลักสำหรับสร้างแผนแนวรับ/แนวต้าน
- M15: หาจังหวะยืนยันตามแผน DAY

WEEK และ DAY ไม่จำเป็นต้องมีสัญญาณตรงกันทุกครั้ง
แต่ต้องแสดงความสอดคล้องหรือความขัดแย้งอย่างชัดเจน
กฎอนุญาตเข้าเมื่อกรอบเวลาขัดแย้งต้องให้ผู้ใช้ยืนยัน

ใช้แท่งที่ปิดแล้วเป็นค่าเริ่มต้นในการยืนยันสัญญาณ
แท่งที่ยังไม่ปิดแสดงได้ แต่ต้องแยกสถานะชัดเจน

ข้อมูลทั้งหมดต้องระบุ:
- สัญลักษณ์
- เวลาเปิดและปิดแท่ง
- เขตเวลา
- ช่วงซื้อขายปกติหรือนอกเวลา
- เวลาได้รับข้อมูล
- สถานะข้อมูลสด ล่าช้า หรือจำลอง

รองรับปฏิทินตลาด วันหยุด และ daylight saving
ห้ามแบ่งแท่ง DAY/WEEK ตามเวลาเครื่องโดยไม่ตรวจเวลาตลาด

ตรวจ corporate actions เช่น stock split
และความสอดคล้องของข้อมูล adjusted/unadjusted
เพื่อไม่ให้ระบบเข้าใจการปรับราคาเป็นการทะลุแนวรับ/แนวต้าน

==================================================
4. แนวรับ/แนวต้านเป็นแกนหลัก
==================================================

ผู้ใช้เน้นแนวรับ/แนวต้านบน DAY
Fibonacci และ Demand/Supply เป็นข้อมูลประกอบ

สร้างโซนจากกฎที่ตรวจสอบได้ เช่น:
- Swing high/low ที่ยืนยันแล้ว
- จุดกลับตัวของราคา
- จำนวนครั้งที่ทดสอบ
- การรวมระดับใกล้กันเป็นโซน
- ความใหม่ของโซน
- การสลับบทบาทแนวรับเป็นแนวต้านหรือกลับกัน

แสดงเหตุผลของทุกโซนและค่าพารามิเตอร์ที่ใช้
ห้ามอ้างว่าโซนแข็งแรงเพียงเพราะเป็น DAY

ก่อนใช้กฎจริง ให้เสนอวิธีและให้ผู้ใช้ยืนยัน:
- จำนวนแท่งย้อนหลัง
- วิธีหา swing
- ความกว้างโซน
- ระยะขั้นต่ำระหว่างการทดสอบแต่ละครั้ง
- เงื่อนไขโซนถูกทำลาย
- วิธีจัดลำดับโซนสำคัญ

ห้ามใช้ข้อมูลอนาคตเพื่อยืนยัน swing หรือสร้างสัญญาณย้อนหลัง

รองรับผู้ใช้:
- วาดหรือแก้โซนเอง
- ล็อกโซน
- ปิดโซนที่ไม่ต้องการ
- แยกโซนอัตโนมัติกับโซนที่ผู้ใช้สร้าง
- ดูประวัติการแก้ไขและผู้สร้างโซน

แยกประเภทแผน:
- รอการเด้งจากโซน
- รอการทะลุและกลับมาทดสอบ

สร้างและทดสอบทีละกลยุทธ์
อย่ารวมหลายกลยุทธ์ตั้งแต่ต้นโดยไม่ได้รับอนุมัติ

==================================================
5. อินดิเคเตอร์และเครื่องมือเสริม
==================================================

รองรับ:
- EMA 15, 50, 100, 200
- ATR(14)
- Volume
- Fibonacci
- Demand/Supply

หน้าที่:
- EMA: ประกอบการประเมินแนวโน้มและโมเมนตัม
- ATR: ประเมินความผันผวน ไม่ใช่ตัวบอกทิศทาง
- Volume: ประกอบการตรวจแรงสนับสนุนของการเคลื่อนไหว
- Fibonacci: ระดับประกอบจาก swing ที่ระบุชัด
- Demand/Supply: โซนประกอบจากฐานราคาและการเคลื่อนออก

Fibonacci ต้องบันทึก:
- จุดเริ่มและจุดจบ
- เวลาและราคาของ swing
- ทิศทางที่ลาก
- ระดับที่เลือกใช้
- ผู้สร้างหรือวิธีอัตโนมัติที่ใช้

Demand/Supply ต้องมีกฎ:
- รูปแบบฐาน
- ความแรงของการเคลื่อนออก
- ขอบเขตโซน
- การทดสอบซ้ำ
- เงื่อนไขหมดอายุหรือถูกทำลาย

ห้ามถือว่าเครื่องมือหลายตัวที่ใช้ราคาเดียวกัน
เป็นหลักฐานอิสระหลายชุดโดยอัตโนมัติ

อย่าเพิ่ม RSI, MACD หรืออินดิเคเตอร์อื่นเอง
เว้นแต่เสนอเหตุผลและได้รับอนุมัติ

==================================================
6. แผนและเงื่อนไขเข้า/ออก
==================================================

แต่ละแผนต้องมี:
- Plan ID และ strategy version
- สัญลักษณ์และ TimeFrame
- เวลาสร้างและอายุแผน
- โซน DAY ที่เกี่ยวข้อง
- บริบท WEEK
- ทิศทางและเหตุผล
- เงื่อนไขยืนยันบน M15
- เงื่อนไขยกเลิกแผน
- ราคาเข้าที่เสนอ
- SL/TP ที่เสนอ
- ความเสี่ยงและต้นทุนประมาณการ
- ภาพและข้อมูลที่ใช้ ณ เวลานั้น

สถานะแผน:
- รอเงื่อนไข
- พร้อมพิจารณา
- รอผู้ใช้ยืนยัน
- ส่งคำสั่งแล้ว
- เปิดสถานะ
- ปิดสถานะ
- ยกเลิก
- หมดอายุ
- ถูกระงับเพราะข้อมูลหรือความเสี่ยง

อย่าบังคับเลือกซื้อหรือขายทุกครั้ง
“รอดู” และ “ไม่เข้า” เป็นผลลัพธ์ที่ถูกต้อง

ค่าเริ่มต้น:
- โหมดอ่านอย่างเดียว
- ปิดการส่งคำสั่ง
- ปิดการขาย Short จนกว่าผู้ใช้ยืนยัน
- ห้ามเปลี่ยนกฎระหว่างเทรดเอง

==================================================
7. Money Management, SL และ TP
==================================================

ทุนตั้งต้นประมาณ 3,000 บาท
เป็นค่าประมาณที่ผู้ใช้แก้ไขได้ ไม่ใช่เงินพร้อมใช้จริงโดยอัตโนมัติ

แยก:
- ทุนที่ผู้ใช้ตั้งสำหรับวางแผน
- Balance, Equity และ Free Margin จากบัญชีจริงหรือ Demo
- สกุลเงินบัญชีและอัตราแลกเปลี่ยนที่ใช้

ค่าที่ยังไม่ยืนยันต้องเว้นไว้:
- ความเสี่ยงสูงสุดต่อรายการ
- ขาดทุนสูงสุดต่อวัน
- จำนวนสถานะพร้อมกัน
- ความเสี่ยงรวมของสถานะเปิด
- เกณฑ์ผลตอบแทนต่อความเสี่ยงขั้นต่ำ

หากค่าเหล่านี้ยังไม่ครบ:
- แสดงตัวอย่างคำนวณได้
- ห้ามส่งคำสั่ง รวมถึง Demo

หลักการ SL:
- อิงจุดที่ทำให้แผนใช้ไม่ได้และโครงสร้างราคา
- มี volatility buffer ที่ตั้งค่าและทดสอบได้
- ประเมิน ATR บน DAY/M15 ให้สัมพันธ์กับระยะถือ
- ห้ามใช้ ATR M15 อย่างเดียวทำให้ SL ของแผน DAY แคบเกินไป
- ห้ามวาง SL เป็นระยะคงที่อย่างเดียว
- SL กว้างขึ้นต้องลดขนาดสถานะ
- ห้ามขยาย SL หลังเปิดเพื่อหลีกเลี่ยงการยอมรับขาดทุน

หลักการขนาดสถานะ:
- คำนวณจากเงินเสี่ยงและผลขาดทุนถึง SL
- ใช้ข้อกำหนดสัญญาและเครื่องมือคำนวณของ MT5 เมื่อรองรับ
- รวมการแปลงสกุลเงินและต้นทุนที่เกี่ยวข้อง
- ตรวจ minimum volume, volume step และ maximum volume
- ปัดขนาดลง ไม่ปัดขึ้นจนเกินวงเงินเสี่ยง
- หากขนาดขั้นต่ำเสี่ยงเกินกำหนด ให้ “ไม่เข้า”
- ห้ามลดระยะ SL เพื่อให้เปิดขนาดขั้นต่ำได้

หลักการ TP:
- อิงโซนเป้าหมาย DAY และความคุ้มเสี่ยงหลังต้นทุน
- หากแนวต้าน/แนวรับขวางก่อนเป้าหมาย ให้แสดงข้อจำกัด
- ถ้าไม่ผ่านเกณฑ์ ให้ไม่เข้า
- การแบ่งปิดหรือ trailing stop ต้องเป็นกฎที่ผู้ใช้อนุมัติ

ประเมินความเสี่ยงร่วมของหุ้นกลุ่มเดียวกัน
ห้ามถือว่าการเปิดหลายหุ้นเท่ากับกระจายความเสี่ยงเสมอ

แสดงว่า SL ไม่รับประกันราคาปิด
และ gap/slippage อาจทำให้ขาดทุนเกินค่าประมาณ

ห้ามใช้ Martingale หรือเพิ่มสถานะเพื่อแก้ขาดทุนเป็นค่าเริ่มต้น

==================================================
8. การเทียบราคากับ MT5/Exness
==================================================

ห้ามคัดลอกระดับราคา Webull ไปเป็น SL/TP ของ CFD โดยไม่ตรวจสอบ

ก่อนเชื่อมส่งคำสั่ง:
- ตรวจว่าเป็นสินทรัพย์อ้างอิงและหน่วยราคาที่ตรงกัน
- เก็บราคา Webull และ Bid/Ask ของ Exness พร้อม timestamp
- ตรวจอายุข้อมูลและความคลาดเคลื่อน
- เสนอวิธีเทียบระดับราคาและข้อจำกัดให้ผู้ใช้อนุมัติ
- ไม่สมมติว่าส่วนต่างราคาคงที่
- คำนวณความเสี่ยงใหม่จากราคาซื้อขายจริงของ Exness

หากการเทียบไม่น่าเชื่อถือ:
- งดเปิดสถานะ
- แจ้งเหตุผล
- ไม่เปลี่ยนไปใช้กราฟ Exness สร้างสัญญาณเอง

ตรวจ:
- Spread
- Trading session
- Stop/freeze levels
- Margin
- ขนาดสัญญา
- Commission และค่าถือข้ามคืนตามบัญชีจริง

==================================================
9. ถือข้ามคืนและข่าว
==================================================

ผู้ใช้อนุญาตให้ถือข้ามคืนได้
แต่ต้องมี:
- ค่าถือข้ามคืนและต้นทุนที่ตรวจสอบได้
- คำเตือน gap
- วันประกาศผลประกอบการเมื่อมีแหล่งข้อมูลที่เชื่อถือได้
- การตั้งค่าถือข้ามสุดสัปดาห์แยกต่างหาก

หากไม่มีข้อมูลข่าวหรือปฏิทิน:
- แสดงว่าไม่ทราบ
- ห้ามสมมติวัน
- อนุญาตให้ผู้ใช้กรอกเหตุการณ์เอง

ก่อนซื้อขายให้ผู้ใช้ยืนยันนโยบาย:
- งดเปิดก่อน/หลังข่าวกี่ชั่วโมง
- ถือผ่านประกาศผลประกอบการได้หรือไม่
- การจัดการสถานะก่อนตลาดปิด

==================================================
10. ภาพกราฟและการวิเคราะห์ภาพ
==================================================

สร้างกราฟจากข้อมูลที่ได้รับอนุญาตในเว็บของระบบ
และรองรับการจับภาพกราฟของระบบเอง

หากต้องจับภาพจากแพลตฟอร์มภายนอก
ต้องตรวจสิทธิ์และวิธีเข้าถึงก่อน ห้ามหลบข้อจำกัด

ตัวอย่างโครงสร้าง:
screenshots/
  YYYY-MM-DD/
    SYMBOL/
      DAY/
      WEEK/
      M15/

ชื่อไฟล์:
SYMBOL_TF_YYYY-MM-DD_HH-mm-ss_EVENT-ID.png

เก็บ metadata คู่กับภาพ:
- เวลา UTC และเวลาที่แสดง
- เขตเวลา
- สัญลักษณ์และ TimeFrame
- แหล่งข้อมูลและสถานะความล่าช้า
- Plan ID / Signal ID
- เวอร์ชันกลยุทธ์
- โซนและพารามิเตอร์ที่ใช้

จับภาพเมื่อ:
- สร้างหรือแก้แผน
- เกิดสัญญาณ
- ส่งคำสั่ง
- ปิดสถานะ
- เกิดข้อผิดพลาดสำคัญ

ตั้งรอบจับภาพเพิ่มเติมและระยะเก็บรักษาได้
มีการจำกัดพื้นที่ ป้องกันไฟล์ซ้ำ และสำรองข้อมูล

การวิเคราะห์ภาพเป็นโมดูลเสริมเท่านั้น:
- ต้องมีโมเดลหรือบริการรองรับภาพจริง
- แสดงค่าใช้จ่ายและสถานะพร้อมใช้
- ปิดได้โดยไม่กระทบการคำนวณหลัก
- ไม่ใช้ภาพเป็นแหล่งราคาหรือสร้างคำสั่งเพียงอย่างเดียว
- ผลขัดแย้งกับตัวเลขให้แจ้งตรวจสอบ
- ห้ามแคปข้อมูลล็อกอิน ข้อมูลลับ หรือข้อมูลบัญชีที่ไม่จำเป็น

==================================================
11. เว็บแดชบอร์ด
==================================================

สร้างหน้าหลัก:
1. Overview
   - สถานะข้อมูลและการเชื่อมต่อ
   - หุ้นที่ติดตาม
   - แผนล่าสุด
   - สถานะเปิดและความเสี่ยงรวม
   - สถานะอ่านอย่างเดียว/Demo/Live ชัดเจน

2. Charts
   - WEEK, DAY, M15
   - โซนแนวรับ/แนวต้าน
   - EMA, ATR, Volume
   - เปิด/ปิด Fibonacci และ Demand/Supply
   - เครื่องมือวาดโซนด้วยมือ

3. Plans & Signals
   - เหตุผล เงื่อนไข สถานะ และอายุแผน
   - SL/TP ขนาดสถานะและความเสี่ยง
   - เหตุผลที่ไม่เข้า

4. Orders & Positions
   - คำสั่งที่ส่งและผลตอบกลับ
   - Broker ticket
   - Requested price และ filled price แยกกัน
   - ต้นทุนและกำไร/ขาดทุนจริง
   - เชื่อมกลับไปหาแผนและภาพ

5. Journal & Gallery
   - ค้นตามวัน หุ้น TimeFrame และสถานะ
   - แสดงภาพและ metadata
   - ดูข้อมูล ณ เวลาตัดสินใจ ไม่ใช้ข้อมูลปัจจุบันแทนอดีต

6. Settings
   - ทุนและข้อจำกัดความเสี่ยง
   - สินทรัพย์และการจับคู่สัญลักษณ์
   - กลยุทธ์ พารามิเตอร์ และเขตเวลา
   - ภาพ พื้นที่จัดเก็บ และการสำรอง
   - การแจ้งเตือน

7. System Health
   - ความสดของข้อมูล
   - ข้อมูลหาย/ผิดปกติ
   - สถานะ worker และ MT5
   - ข้อผิดพลาดล่าสุด

เหตุผลต้องมาจากกฎและข้อมูลที่เกิดขึ้นจริง
ห้ามสร้างเหตุผลย้อนหลังขึ้นเอง
ข้อความ AI เป็นคำอธิบายเสริม ต้องแยกจากผลคำนวณ

==================================================
12. รอบการทำงานและการใช้ AI
==================================================

ไม่วิเคราะห์ทุกอย่างใหม่ทุก tick

ใช้ event-driven processing:
- WEEK ปิด: อัปเดตบริบทใหญ่
- DAY ปิด: อัปเดตโซนและแผน
- M15 ปิด: ตรวจจังหวะยืนยัน
- Order/Position event: อัปเดตการซื้อขาย
- ข้อมูลผิดปกติ: ระงับและแจ้งเตือน

ใช้ incremental calculation และ cache เมื่อเหมาะสม

คำนวณย้อนหลังใหม่เมื่อ:
- ข้อมูลหายหรือถูกแก้ไข
- เปลี่ยนพารามิเตอร์
- มี corporate action
- ตรวจพบ state ไม่สอดคล้อง

AI ไม่ต้องทำงานทุก tick
ใช้เพื่อสรุปเหตุผลหรือวิเคราะห์ภาพเฉพาะเหตุการณ์ที่กำหนด
หาก AI ใช้งานไม่ได้ ระบบกฎหลักต้องยังทำงานได้

ห้ามให้ AI เปลี่ยนกลยุทธ์ วงเงินเสี่ยง หรืออนุมัติคำสั่งเอง

==================================================
13. ความปลอดภัยและเครื่องส่วนตัว
==================================================

เลือกเทคโนโลยีหลังตรวจ OS และวิธีเชื่อม MT5
เสนอ architecture ที่ติดตั้งและดูแลบนเครื่องผู้ใช้ได้จริง

ต้องมี:
- การเก็บ secrets นอก source code
- ไม่ขอรหัสผ่าน/API key ผ่านข้อความสนทนา
- ไม่บันทึกข้อมูลลับใน log
- แดชบอร์ดรับเฉพาะ localhost เป็นค่าเริ่มต้น
- การยืนยันตัวตนหากเปิดเข้าถึงจากเครือข่าย
- backup และวิธี restore
- graceful shutdown และ startup recovery

เมื่อเริ่มโปรแกรมใหม่:
- ตรวจสถานะบัญชี ออเดอร์ และสถานะเปิดจาก MT5
- กระทบยอดกับฐานข้อมูลก่อนอนุญาตคำสั่งใหม่
- ห้ามส่งซ้ำเพราะ restart หรือ timeout

ใช้ unique IDs และ idempotency
เมื่อไม่ทราบว่าคำสั่งสำเร็จหรือไม่ ให้ตรวจโบรกก่อน retry

ก่อนซื้อขายต้องมี SL ฝั่งโบรกที่ตรวจยืนยันได้
หากตั้งการป้องกันไม่สำเร็จ ต้องมีแผน fail-safe ที่ผู้ใช้อนุมัติ

ปุ่มหยุดต้องแยก:
- หยุดเปิดออเดอร์ใหม่
- หยุด automation แต่ยังติดตามสถานะ
- ปิดสถานะฉุกเฉินพร้อมการยืนยัน

อย่าให้เกณฑ์เปิดออเดอร์ใหม่ขัดขวางการปิดฉุกเฉิน

แจ้งเตือนเมื่อเครื่อง sleep อินเทอร์เน็ตขาด หรือ MT5 ปิด
อธิบายว่าตอนเครื่องไม่ทำงาน ระบบดูแลแบบ local จะไม่ทำงาน
แม้คำสั่งป้องกันที่โบรกยืนยันแล้วอาจยังคงอยู่

==================================================
14. การทดสอบ
==================================================

ต้องมี:
- Unit tests ของอินดิเคเตอร์ โซน MM และเวลา
- Integration tests ของ data adapter และ MT5
- การทดสอบข้อมูลขาด ล่าช้า หรือซ้ำ
- การทดสอบ restart และคำสั่งตอบกลับไม่ชัดเจน
- การทดสอบขนาดขั้นต่ำเกินวงเงินเสี่ยง
- การทดสอบ manual zones และประวัติแก้ไข

Backtest ต้อง:
- ไม่มี look-ahead bias
- คำนึงถึงเวลาที่ swing ยืนยันได้จริง
- รวม spread, slippage, commission และค่าถือสถานะ
- รองรับ gap และตลาดปิด
- แยกข้อมูลปรับกลยุทธ์กับ out-of-sample
- เปิดเผยข้อจำกัดเมื่อใช้ราคา Webull จำลอง CFD ของ Exness
- ไม่ถือว่าผลบนหุ้นเท่ากับผล CFD โดยอัตโนมัติ

รายงาน:
- จำนวนรายการ
- Win rate
- ผลตอบแทนสุทธิและ Expectancy
- Profit factor
- Maximum drawdown
- ชุดขาดทุนต่อเนื่อง
- ความเสี่ยงและต้นทุน
- ผลแยกตามหุ้นและสภาพตลาด

ห้ามสรุปว่ากลยุทธ์ดีจาก win rate อย่างเดียว
และห้ามรับประกันว่าผลย้อนหลังจะเกิดซ้ำ

15. แผนพัฒนาและจุดอนุมัติ
==================================================

ขั้น 1: ตรวจความเป็นไปได้
- ตรวจ OS, Webull, MT5 และสิทธิ์ข้อมูล
- ถามข้อมูลที่จำเป็น
- เสนอ architecture, ข้อจำกัด และค่าใช้จ่าย
- หยุดรออนุมัติ

ขั้น 2: ระบบอ่านอย่างเดียว
- Data adapter / mock adapter
- ฐานข้อมูลและกราฟ
- อินดิเคเตอร์และโซน
- จัดเก็บภาพ
- ไม่มีการส่งคำสั่ง
- หยุดรออนุมัติ

ขั้น 3: แผนและ MM
- กฎกลยุทธ์ที่ผู้ใช้ยืนยัน
- Plan/Signal state machine
- SL/TP และขนาดสถานะ
- Journal และเหตุผลไม่เข้า
- หยุดรออนุมัติ

ขั้น 4: การทดสอบ
- Automated tests
- Backtest และ out-of-sample
- รายงานข้อจำกัด
- หยุดรออนุมัติ

ขั้น 5: Demo execution
- เชื่อม MT5 หลังค่าความเสี่ยงครบ
- ตรวจการจับคู่ราคาและเงื่อนไขสัญญา
- เริ่มแบบผู้ใช้ยืนยันคำสั่ง
- ทดสอบความผิดพลาดและ recovery
- หยุดรออนุมัติ

Live trading อยู่นอกขอบเขตการเปิดใช้งานครั้งแรก
ต้องผ่านการตรวจและได้รับอนุมัติแยกต่างหาก
ห้ามเปิด Live เพียงเพราะการติดตั้งสำเร็จ

16. สิ่งที่ต้องส่งมอบและการเริ่มงาน
==================================================

ส่งมอบ:
- Source code พร้อมโครงสร้างโปรเจกต์
- คู่มือติดตั้งและใช้งาน
- ตัวอย่าง config ที่ไม่มี secrets
- Database schema
- Automated tests
